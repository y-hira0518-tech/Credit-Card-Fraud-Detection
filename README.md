# Credit Card Fraud Detection

Kaggleの Credit Card Fraud Detection データセットを題材に、極端なクラス不均衡データへの対策・モデル比較・閾値調整までを行った分析です。

## 環境

- Google Colab
- Kaggleデータ取得は `kaggle.json` を `files.upload()` でアップロードする方式(データセット: `mlg-ulb/creditcardfraud`)

## データの特性

- 284,807件中、不正利用(Class=1)は492件、全体の0.1727%という極端な不均衡
- 欠損値なし
- V1〜V28はPCA(主成分分析)により匿名化済みの特徴量。平均は概ね0だが、標準偏差はV1(1.96)〜V28(0.33)まで不揃い(PCAは分散順に並ぶ性質上、分散を1に揃えるスケーリングまでは行われていない状態)

## 前処理・特徴量エンジニアリング

- **Amount(取引額)**: 歪度が16.98と極端に右へ歪んでおり、`log1p`変換で0.16まで大幅に改善したため採用。クラス別のパーセンタイル比較では、中央値は不正利用の方が低い(9.25 vs 22.00)一方、99パーセンタイルでは逆転する(1357.43 vs 1016.97)という、少額・高額それぞれの不正が混在する傾向を確認
- **Time(経過時間)**: 生の通し秒数のままでは意味を持たないため、`Hour_of_day`(= (Time % 86400) // 3600、1日の中の時間帯)に変換。時間帯別の不正発生率を確認したところ、深夜2時台(1.71%)が全体平均(0.17%)の約10倍と際立って高く、有効な特徴量と判断
- **V1〜V28**: 他の数値特徴量と同様にStandardScalerを適用(木系モデルには理論上不要だが、パイプラインを分けずに統一)

## クラス不均衡対策

**SMOTE(少数派過剰サンプリング手法)は不採用としました。** 理由は2点です。

1. 交差検証のfold内で正しくSMOTEを適用するには専用のパイプライン設計が必要な上、V1〜V28という28次元のPCA圧縮空間では、単純な線形補間による合成サンプルが不自然な位置に生成されやすい(次元の呪い)
2. 284,807件規模のデータに対し、5-fold CV×Optunaの試行を重ねる中でSMOTEの近傍探索処理を都度行うと、計算コストが大きく膨らむ懸念があった

代わりに、**`class_weight='balanced'`(scikit-learn系)/ `scale_pos_weight`(LightGBM)によるモデル側でのクラス重み付け**と、**PR-AUC(Precision-Recall AUC)を主指標とした評価**、**F1スコア最大化による閾値調整**を組み合わせて対応しました。

## モデル選定(計算コストによる絞り込み)

284,807件という規模に対し、以下のモデルは計算コストの高さから除外しました。

- **SVM**: 学習データ数に対し計算量が2〜3乗のオーダーで増加するため、事前に除外
- **KNN**: 予測のたびに全学習データとの距離計算が必要なため、Optuna探索が完了しないほど時間がかかり除外
- **Random Forest**: `n_estimators`・`max_depth`の探索範囲とこのデータ規模の組み合わせで、120秒のタイムアウト内での試行が現実的でなく除外

最終的に **LightGBM**(ヒストグラムベースの高速な分割探索により大規模データに強い)のみで比較・チューニングを行いました。

## ハイパーパラメータチューニング

当初 `scale_pos_weight` をクラス比率(577.88)に固定して探索したところ、PR-AUC 0.7350(Optuna 5試行、120秒)にとどまり、不均衡対策なしのロジスティック回帰ベースライン(0.7439)をわずかに下回りました。極端な重み付けが木の学習を不安定にしている可能性を踏まえ、`scale_pos_weight` 自体をOptunaの探索対象(1〜577.88、対数スケール)に加え、タイムアウトを600秒に延長したところ、以下のように改善しました。

| 設定 | PR-AUC(5-fold平均) | 試行回数 |
|---|---|---|
| scale_pos_weight固定(577.88) | 0.7350 | 5 |
| scale_pos_weight探索(最良値65.62) | 0.8341 | 20 |

不均衡比率をそのまま重みに使うのではなく、適切な重みを探索することの重要性を示す結果になりました。

## 閾値調整(F1スコア最大化)

デフォルトの閾値0.5ではなく、5-fold交差検証の各foldでF1スコアが最大になる閾値を求め、その平均値を採用しました。

- 採用閾値: 0.9357(5-fold平均、標準偏差0.0626)
- 各foldのF1スコア: 0.826〜0.883、適合率0.89〜0.98、再現率0.77〜0.84

`scale_pos_weight`による重み付けの影響で、モデルが出力する予測確率自体が不正クラス側に引き上げられているため、最適な閾値も通常より高い位置(0.9台)でバランスが取れる結果になっています。

## モデル解釈について

特徴量の大半(V1〜V28)がPCAで匿名化済みの変数であり、個々の変数が何を意味するか解釈できないため、SHAP分析は省略しました。
